## 2026-11-24 — M0: project setup and pipeline check

**Built**
- Confirmed tools: Godot 4.7.2 stable (.NET build, used for GDScript only) in `Downloads`, Blender 4.0.2 in `Program Files`. Paths recorded in `CLAUDE.md`.
- `CLAUDE.md` (standing rules) and `docs/GAME_DESIGN.md` (design reference).

- **Physics: Jolt Physics** (built into Godot since 4.4) selected in `physics/3d/physics_engine`.
- Input map generated by `tools/godot/setup_project.gd` (keyboard by physical key so WASD works on any layout, plus gamepad): move (WASD / left stick), look (right stick; mouse look is read from mouse motion), sprint (Shift / L3), jump (Space / A), vehicle enter-exit (F / Y), interact (E / X), pause (Esc / Start).
- `tools/blender/rotd_mesh.py`: shared mesh builder (boxes, frustums, tubes, spheres, prisms, flat shading, box-projected UVs, auto-oriented faces), material helper (sRGB hex → Principled BSDF), GLB export.
- `tools/blender/test_cube.py` → `assets/models/test/prop_test_cube.glb` (1 m cube, base pivot, `-colonly` collision).
- `tests/smoke_test.tscn` + `smoke_test.gd`: checks project settings, input map, the imported cube (one mesh, one auto-built StaticBody3D, base pivot) and drops a physics ball onto the cube's imported collision (rests at y = 1.50 as expected). `tests/error_catcher.gd` (a `Logger`) makes any engine/script error fail the test. Exit code 0/1.

**Broke / notes**
- `--import` prints `ERROR: .NET Sdk not found` because the editor is the .NET build and no .NET SDK is installed. Not a project error (no C#), and it doesn't appear at runtime. Documented in `CLAUDE.md` as the one accepted message.
- Godot drops settings equal to their defaults when it saves `project.godot` (`physics_ticks_per_second=60`, `rendering_method="forward_plus"`), so they don't appear in the file. Expected.
- Kept `*.import` / `*.uid` files in git (Godot's recommendation): they hold import settings and resource UIDs.

## 2026-11-24 — M1: playable prototype

**Built**

  - `road_kit.py`: 12 m road straight (4 lanes, left-hand traffic markings), crosswalk variant (zebra + stop line), junction, 4 × 8 m sidewalk and 4 × 4 m corner with black/yellow painted kerbs. Sidewalk collision is **bevelled at the kerb (~27°)** so the capsule can step up without a step-up hack.
  - `buildings.py`: 3 shop-house variants (shutter/open shopfront, striped awning, blank sign + neon strip, balcony, rooftop water tank), 2 apartment blocks on stilts (walk-under parking, balconies), 2 glass office towers (floor bands, corner fins, neon crown, one with a spire), temple **gopuram** (7 painted tiers with pavilions, barrel-vault crown, golden finials, walk-through gateway with a bevelled plinth) and a small shrine. 330 to 2,800 tris each, box-based `-colonly` collision.
  - `props.py`: streetlight (warm emissive lens), leaning coconut palm, red-and-white striped temple compound wall.
  - `rotd_mesh.py` gained `convex_hull()` for bevelled collision shapes.
- **Test block** (`scenes/world/test_block.tscn` + `city_block_builder.gd`): 3 × 3 road grid built at runtime from the kit (roads at −60/0/+60 m both ways, 204 m square), crosswalks on every junction approach, sidewalks, raised lots (paved / grass / temple sand), 12 buildings, walled temple compound with a 1 m platform (18° walkable ramp, 50° too-steep ramp), 93 road tiles, 252 sidewalk pieces, 54 streetlights, 49 palms, invisible boundary walls and a safety floor, a ground plane beyond the walls.
- **Lighting** (`LightingPreset` resource + `WorldLighting`): late-afternoon sun (21° elevation from WSW, warm), procedural sky, sky ambient, exponential fog with sun scatter, ACES tonemapping, soft glow, SSAO, mild saturation and contrast boost.
- **Player** (`scenes/player/player.tscn`): capsule with a magenta facing "nose"; camera-relative walk (Ctrl / light stick) / run / sprint (Shift, uses stamina), jump with coyote time and input buffering, heavier fall gravity, 46° slope limit with floor snapping, states IDLE / WALK / RUN / SPRINT / JUMP / FALL / LAND with a `state_changed` signal. - **Camera** (`ThirdPersonCamera`): Yaw → Pitch → SpringArm3D (sphere-cast collision) → Camera3D; mouse and right-stick look, pitch clamp (−65° to +35°), separate horizontal/vertical follow smoothing of the player's *interpolated* transform, FOV kick while sprinting. Tunables in `player_camera.tres`.
- **Physics interpolation** switched on in the project, so movement and camera stay smooth on screens faster than the 60 Hz physics tick.
- **UI** (built in code on one theme, `UIStyle`): main menu (New Game, Continue disabled, Settings, Controls, Credits, Exit) over an animated neon-skyline shader; settings panel (master/music/effects volume, mouse sensitivity, invert look; applied live, saved to `user://settings.cfg` on close); controls screen generated from the input map; credits including the Godot licence text; pause menu (Resume, Settings, Main Menu, Quit; really pauses the tree and frees the mouse); HUD with health and stamina bars and an F3 FPS counter. Keyboard, mouse and gamepad navigable.
- **Audio**: buses Master → Music, SFX, Ambience, UI (`default_bus_layout.tres`). `AudioManager` autoload with pooled voices; all sounds synthesised in code (`AudioSynth`): UI blips, footsteps (paced by speed), landing thud, a seamless 4 s ambient menu loop built on a worker thread.
- **Autoloads**: `Settings`, `AudioManager` (written by `tools/godot/setup_project.gd`, which now also writes the main scene, physics interpolation and the bus layout).
- **Tests**: the smoke test now drives the real flow (main menu → settings sliders → controls/credits → New Game → spawn → W for 2 s → sprint → jump → kerb, ramps and gateway → camera → HUD → pause, frozen while paused → resume → Main Menu) with 15 checks and fails on any logged engine/script error. It never writes the user's settings (`Settings.persist = false`). New `tests/screenshot.tscn` renders a scene in a window, saves a PNG and prints render stats.

**Broke / fixed**
- Menu buttons were hard to read over the shader skyline, and the disabled *Continue* button looked broken → darkened the left third of the background shader; made the disabled style more opaque. (Found via screenshot.)
- Player capsule was nearly black against the asphalt → lighter body colour.
- *Invert look* rendered as an empty bar with a tiny default switch → replaced with an ON/OFF toggle button in the menu style.
- Credits text could only be scrolled with the mouse wheel → up/down keys and D-pad now scroll it.

**Performance note (not the M3 baseline):** at the spawn view, the windowed run on this machine reports 60 FPS (VSync-capped), ~890 draw calls, ~124 k primitives, 151 MB video memory. Draw calls are high because every kerb, light and palm is its own instance. MultiMesh and chunking in M3 are expected to bring this down.

## 2026-11-24 — M2: first car

**Built**
- **Physics choice:** Godot's `VehicleBody3D` + `VehicleWheel3D` running on the built-in **Jolt Physics** engine (already the project's engine since M0). A probe confirmed on this build: forward is +Z, positive steering turns left, `VehicleWheel3D.brake` is an impulse per physics step (so brake forces are applied as force × delta), and Jolt reports body contacts for damage.
- **Sedan model** (`tools/blender/vehicles.py`, deterministic): `veh_sedan_body.glb` (1,204 tris): side profile with real wheel-arch cut-outs, extruded and bevelled, tapered tinted-glass cabin, painted roof and pillars, door seams, handles, mirrors, headlights, grille, blank number plates, tail and reverse lights, exhaust. `veh_sedan_wheel.glb` (568 tris): tyre plus five-spoke rim. Lens materials are named so the game can make them glow. No baked collision (the scene has two convex hulls: lower body and cabin).
- **`VehicleStats` resource** (`resources/vehicles/sedan_stats.tres`): mass, centre of mass, drive layout, engine force and power, top speed, reverse, drag, rolling resistance, engine braking, downforce, brakes and bias, handbrake, parking brake, steering lock (with high-speed falloff), steer speeds, suspension (stiffness, rest length, travel, damping, max force, roll influence), tyre grip, cosmetic gearbox, damage, flip recovery.
- **`VehicleController`** (`scenes/vehicles/sedan.tscn`): drivers only call `set_controls(throttle, brake, steer, handbrake)`, so AI traffic can use the same car later. Front-wheel drive; brake pedal reverses from a standstill; power-limited push with a top-speed limiter; per-wheel brake bias; handbrake locks and loosens the rear; parking brake when empty; `teleport()` that doesn't count as a crash.
- **Components:** `VehicleEngine` (simulated rpm, 5-speed automatic for sound and HUD), `VehicleDamage` (crash = sudden speed change while touching something, health, grey/dark/black engine smoke from GPU particles, engine dies at zero), `VehicleLights` (headlight spotlights and glowing lenses, brake lights, reverse lights), `VehicleAudio` (3D engine note pitched by rpm, two-tone horn, tyre screech from wheel slip, crash, door thunk; all synthesised), `VehicleRecovery` (rights an occupied car stuck on its side or roof).
- **Player:** new states ENTER_VEHICLE, IN_VEHICLE, EXIT_VEHICLE. `VehicleInteractor` finds the nearest free car within 3 m (F / Y), enters by the nearer front door, and on exit brakes first if moving, then picks the first clear spot: driver's door (right-hand drive), passenger door, behind, in front, roof. `PlayerDrivingInput` maps the new driving actions to the car. The player now collides with vehicles (mask world + vehicles).
- **Cameras:** `VehicleCamera` with chase mode (spring arm, drops back and widens with speed, swings behind the car after you stop looking) and hood mode; V / Back toggles. `CameraTransition` blends between the on-foot and vehicle cameras on getting in (0.6 s) and out (0.45 s).
- **HUD:** neon speedometer (speed arc, ticks, digits, gear, rev arc) with an orange car-health bar; "F  GET IN" prompt; a one-off driving reminder. Controls screen gains On foot / Driving / General sections.
- **Input map:** `vehicle_accelerate` (W, Up, RT), `vehicle_brake` (S, Down, LT), `vehicle_steer_left/right` (A/D, arrows, left stick), `vehicle_handbrake` (Space, RB), `vehicle_horn` (H, L3), `vehicle_headlights` (L, D-pad up), `vehicle_camera` (V, Back).
- **Tests:** smoke test now runs 26 checks including 11 vehicle ones (parked state, walk-into, prompt, get in, drive, brake, reverse, steer, cameras, horn, lights, crash damage, smoke, pause while driving, get out stopped / at speed / blocked door). New `tests/vehicle_test.tscn` drives the sedan on a 4 km test pad and prints a handling report with sanity ranges. Screenshot tool gained `--drive`, `--throttle`, `--steer`, `--hood`, `--health`, `--headlights`.

**Handling report (sedan, as tuned)**
- 0-50 km/h 3.5 s, 0-100 km/h 7.8 s, top speed 171 km/h (limiter 175), straight-line drift 0.00 m.
- 100-0 km/h in 42.9 m (0.88 g). Reverse tops out at 28 km/h.
- Turning circle 10.5 m. Full lock at 60 km/h: 1.30 g, 14 m radius; at 100 km/h: 1.42 g, 42 m radius (understeers), body tilt never above 3°.
- Handbrake + full lock for 1 s at 60 km/h: 94° of rotation vs 42° without.
- Crashes into a wall: 10 km/h no damage, 30 km/h -160, 60 km/h -430 (of 1000).

**Broke / fixed**
- Top speed stuck at 93 km/h: Godot's default linear damping (0.1/s) acted as a second drag on the car → the car replaces it with 0 and models drag and rolling resistance itself.
- Test bug: the 40 s acceleration run drove off the end of a 2 km test pad and into the crash-test wall (which then wrecked the car for every later check). Bigger pad, runway start, wall moved aside.
- Teleporting a car at 171 km/h to a standstill counted as a 171 km/h crash → `VehicleController.teleport()` emits `teleported` and the damage tracker resets. Flip recovery uses it too.
- First tyre-grip guess (3.0) gave 2.7 g cornering and no understeer, so the car would turn like it was on rails → grip 1.4 front / 1.55 rear (about 1.3 g, mild understeer at the limit).
- Exit at speed must brake whichever way the car is rolling: pressing only the brake pedal while rolling backwards reverses → the exit brake presses both pedals (the controller treats that as pure braking).
- "2 ObjectDB instances were leaked at exit" warnings (also present in M1): the menu music's playback when quitting mid-song. `AudioManager.quit_game()` stops every player (including 3D car sounds) and waits 0.1 s before quitting; the menu Exit, pause Quit and both test scenes use it.
- Smoke puffs looked like solid white balls in the first screenshot → smaller, more transparent particles.

**Performance note:** driving view at spawn in the windowed run: 60 FPS (VSync-capped), ~710-800 draw calls, ~0.1 M primitives, 157 MB video memory. The sedan costs about 21 draw calls (9 body material surfaces plus 3 per wheel), more in shadow passes; worth merging for AI traffic in M4.

## 2026-11-25 — M3: city district (Old Town)

**Built**
- **District plan** (`scripts/world/old_town_layout.gd`, deterministic):
  - Old Town covers 512 × 512 m. The walled temple compound sits in the middle with four gopurams, a central shrine (vimana) and a pillared hall (mandapam), ringed by a lane.
  - **Roads:** main roads (12 m, four lanes) along the gopuram axes and on rings at ±112 and ±184. Lanes (8 m, two lanes) run in between.
  - **Junctions:** 166 in all; the 24 where two main roads cross have traffic lights, plus zebras where main roads meet the temple ring.
  - **Blocks:** sidewalks with kerbs facing the road. Shops line the main roads and houses line the lanes, packed along each frontage with seeded variety, for 1,152 buildings in total.
  - **Special blocks:** a market square (market hall, stalls, flower stalls, handcarts), a temple tank and two parks.
- **New Blender kit** (`tools/blender/old_town.py`):
  - **Road kit v2:** road and lane tiles with left-hand traffic markings, three junction boxes, zebra crossings with stop lines, sidewalk, footpath and corner tiles.
  - **Signal pole:** red, amber and green lamp materials that the game switches.
  - **Props:** two market stalls, a flower stall, a handcart, a bollard and a neem tree.
  - **Buildings:** 14 Old Town row buildings (verandah houses with thinnai seats and clay-tile roofs, shops with shutters, awnings and blank sign boards, a lodge with a rooftop sign frame), plus the market hall, mandapam, vimana and temple tank.
- **Collision as separate convex pieces:** `rotd_mesh.CollisionSet` writes `-convcolonly` objects. The M1 buildings were regenerated the same way, so touching boxes never fuse and gateways stay open.
- **District builder** (`tools/godot/build_old_town.gd`, about 5 s):
  - **Kit baking:** `KitBaker` turns every model into one surface with a shared palette shader (`shaders/palette_lit.gdshader`; colour, roughness, metallic and glow per vertex). Each building is now one draw call; the M1 gopuram had 16 surfaces.
  - **Chunk scenes:** writes 16 binary chunk scenes (128 m, about 30 KB each). Each has:
    - ground tiles and props as `InstanceBatch` MultiMeshes,
    - buildings with a 280 m visibility range and box occluders inside their upper floors,
    - the traffic signals for its junctions,
    - one static body of simple convex shapes (a ground slab, a kerb-bevelled slab per block, building and prop hulls),
    - a baked pedestrian navmesh.
  - **Shared files:** the always-loaded temple landmark scene, the lane graph and the district manifest (`DistrictData`).
- **Streaming:**
  - **`WorldStreamer`:** loads chunks within 200 m of the player on a background thread (one added per frame), frees them beyond 250 m, and freezes parked cars whose ground isn't loaded.
  - **`District`:** the root script of `scenes/world/old_town.tscn`, which also holds the lighting, boundary walls, safety floor, outer ground, spawn and three parked sedans.
  - **New Game:** now starts here.
- **Traffic signals** (`TrafficSignal`, timing in `resources/world/signal_timing.tres`): a two-phase cycle (green 14 s, amber 3 s, all red 2 s). Each junction is offset so they don't all change together. `get_light(axis)` is ready for M4 traffic.
- **Lane graph** (`LaneGraph`, built by `LaneGraphBuilder`): 8,472 nodes, left-hand traffic.
  - **Main roads:** two lanes each way; left turns go from the kerb-side lane and right turns from the inner lane.
  - **Junctions:** curved paths through every junction. Stop lines carry the junction id, the signal axis, and "signalized" or "give way".
  - **District edge:** U-turns where roads meet it.
  - **Connectivity:** fully connected, with no dead ends.
- **Pedestrian navmesh:** baked from block slabs and crossing strips, with buildings, props and the temple as obstacles. Roads are only walkable at crossings. 14,386 polygons, and chunks join exactly at their borders.
- **HUD and debug:** an "OLD TOWN / VELANAGAR" title card on arrival; F3 now also shows draw calls and loaded chunks; a new **F4** debug view draws the lane graph (stop lines in their live light colour) and navmesh edges. Occlusion culling is on in the project.
- **Tests:**
  - **Smoke test:** now 31 checks. It runs in Old Town (district loaded, streaming out and back with the parked car freezing, signal cycle and lamps, lane-graph connectivity and keep-left, navmesh routes and that roads aren't walkable, kerb step-up), and the vehicle checks moved to Ring B.
  - **`tests/player_test.tscn`:** keeps the M1 kerb, ramp and gateway course on the test block.
  - **`tests/perf_baseline.tscn`:** measures FPS and render stats at fixed viewpoints, plus a streaming drive.
  - **Screenshot tool:** gained `--lanes`.

**Performance baseline** (details in `docs/PERFORMANCE.md`; this machine has an Intel UHD Graphics 730 integrated GPU, well below the GTX 1650 target class):
- **Frame rate:** 36-41 FPS at 1920×1080, VSync off, at seven viewpoints with 250-510 draw calls.
- **Where the time goes:** sky only runs at 67 FPS. SSAO off gives 46 FPS, and SSAO plus glow off gives 62 FPS. Per-pixel effects dominate, not draw calls.
- **Streaming drive** across the district at 72 km/h: worst frame 29.6 ms, with no hitch.

**Broke / fixed**
- **Roads, props and gopurams were invisible:** MultiMeshes saved from the headless builder were empty, because a MultiMesh keeps its instances in the rendering server, which headless runs don't have. Now `InstanceBatch` stores the transforms as data and builds the MultiMesh when the chunk loads.
- **Navmesh baking failed** ("root node needs to be inside the SceneTree"): the builder ran in `_initialize`, before the tree was running. It now runs one frame later.
- **Navmesh warnings and height:** baking warned that the agent height and radius weren't multiples of the cell size, and the navmesh floated about 0.35 m above the sidewalks. The agent is now 2.0 × 0.5 m with 0.1 m cell height, and the project's navigation map uses the same 0.1 m (`setup_project.gd`).
- **Navmesh gaps between chunks:** baking exactly the chunk with `border_size` left a 2 m gap. Baking the chunk grown by the border makes the edges meet exactly on the chunk line.
- **Navmesh on rooftops:** rooftops became unreachable navmesh islands. The bake now only covers street level, to 2.6 m, which cut 26% of the polygons.
- **Navmesh queries returned nothing right after chunks loaded:** Godot 4.7 builds navigation regions in the background. The smoke test now waits for the map to sync.
- **Unreachable outer lanes:** 140 outer-lane nodes at the district edge couldn't be reached, because every U-turn fed the inner lane. Each lane now turns into its matching lane.
- **Invisible temple tank:** the block's lot ground and the full-map outer ground plane both covered the sunken pond. The tank block gets ground around the pond, and the outer ground is now a frame around the district.
- **Fused collision boxes:** would have filled verandahs and blocked the gopuram passage once baked into hulls. Fixed with separate convex pieces (`CollisionSet`); `tests/player_test.tscn` still walks through the M1 gopuram.
- **Streaming test expectation:** expected the chunk count to return exactly to its starting value, but a chunk inside the 200 to 250 m hysteresis band is correctly kept. The test now checks that every wanted chunk is loaded.
- **Haze:** too thick looking into the sun at first (0.0055), now 0.0042.

## 2026-11-25 — M4: life in the city

**Built**
- **Pedestrian models** (`tools/blender/characters.py`): a man (shirt and trousers), a woman (long skirt, braid) and an older man (veshti, shoulder towel), 400-456 triangles each. Body, legs and arms are separate parts with their joints at the object origins. Clothes, skin and hair use white materials that the game tints per person.
- **One draw call per person:**
  - `CharacterBaker` bakes a model into one surface, storing in each vertex its part, its joint and which colour channel tints it.
  - `shaders/character.gdshader` swings the limbs in the vertex shader (walk and run cycle, small chat gestures, sitting pose). Colours are per-instance shader parameters.
- **Car paint variety:** the palette shader gained a per-instance tint. `VehicleModel` bakes the sedan body into one surface (plus a lenses surface for the lights) and repaints each traffic car.
- **Benches:** `prop_bench` (stone, with collision) in the temple courtyard, the parks, the market and the tank yard. The district builder writes their 44 seats as `sit_spots` markers.
- **Pedestrians** (`Pedestrian`, `scenes/npc/pedestrian.tscn`): a CharacterBody3D steered by a NavigationAgent3D with avoidance.
  - **States:** wander, idle, chat in pairs face to face, walk to a free bench and sit, run from danger, step aside, and be knocked down. Knocked-down people lie for 3 s, then get up and run from the car.
  - **Knocking people down:** `VehicleBumper` (an Area3D on every car) knocks people down before contact, so the car rolls on instead of stopping dead against a body.
- **`PedestrianManager`:**
  - **Spawning:** keeps the density's count of people on the navmesh 25-80 m from the player (never closer than 60 m in view), some as chatting pairs, and removes them beyond 100 m.
  - **Seats and partners:** hands out bench seats and chat partners.
  - **Alarms:** turns events into reactions. A crash over 10 km/h makes everyone within 18 m run; a horn makes people within 8 m in front of the car step aside; a knockdown makes people within 15 m run; the player walking into someone makes them step aside.
- **Traffic** (`TrafficDriver` drives a full physics sedan through `set_controls`, like the player):
  - **Steering:** pure pursuit along a route of lane nodes, with weighted straight, left and right choices at junctions.
  - **Speed:** slows early for tight turns and stops at stop lines: on red, on amber if it can, briefly at give-way lines, and before turning right across oncoming traffic. A junction counts as clear when nobody is in its middle and no moving car will arrive within 3 s.
  - **Obstacles:** three forward rays keep a gap to anything in front. On roads with two lanes each way, the driver changes lanes to pass a parked or wrecked car if that lane is free.
  - **Patience:** honks after 5 s held up, and pauses 3 s after a crash.
- **`TrafficManager`:** keeps the density's count of cars on lanes 40-110 m from the player (never closer than 95 m in view). It removes cars beyond 130 m, and also cars stuck for 40 s out of view.
- **Lane graph:** new `side_lane` links between the two lanes of each main-road direction (2,200 nodes), used for passing.
- **Settings:** pedestrian and traffic density, Low / Medium / High (12 / 26 / 42 people, 7 / 14 / 22 cars), saved with the other settings and cycled with buttons in the settings panel. All tunables are in `resources/characters/population.tres`, `resources/characters/pedestrian.tres` and `resources/vehicles/traffic_driver.tres`.
- **HUD:** F3 also shows how many cars and people are about.
- **Tests:**
  - **New `tests/traffic_test.tscn`:** density, cars moving without jams or crashes, far cars removed, red light then green, give way, queueing and honking behind a parked car on a one-lane road, passing one on a two-lane road, crash pause.
  - **New `tests/pedestrian_test.tscn`:** density, everyone on the navmesh and none inside buildings, walking, chatting, sitting on a bench, fleeing, crash and horn reactions, knock-down, player bump.
  - **Smoke test:** adds the character and bench assets, the density buttons, cars and people appearing after New Game (then switched off for the deterministic checks), the F3 readout, and no navmesh inside buildings.
  - **Screenshot tool:** gained `--crowd` and `--chase`.
  - **Perf baseline:** gained a city-life table.
- **Version:** 0.4.0, also shown in the main-menu footer, which had still said Milestone 2.

**Performance** (`docs/PERFORMANCE.md`): on this machine's integrated GPU the spawn street runs at 37–38 FPS at every density, the same as with no NPCs, because the frame is GPU-bound. On the CPU, physics including all NPC scripts takes 4.5 ms per step at Medium (headless), against 1.9 ms with no NPCs. The driver scripts take 0.40 ms and the pedestrian scripts 0.97 ms of that.

**Broke / fixed**
- **People inside buildings (an M3 bug, found here):**
  - **Cause:** a building's collision hull is a closed box, and the navmesh bake is cut off at 2.6 m to drop rooftops. Recast saw each hull's floor face with nothing above it and made it walkable, so every building had an unreachable island of navmesh inside.
  - **What it caused:** people spawned there were inside solid geometry and fell through the floor. The manager then quietly replaced them, so it never showed in a count.
  - **Fix:** every solid hull is now added to the bake as a projected obstruction over its own height range, so walk-under roofs like stalls and the pavilion still leave the floor walkable. The navmesh now has 11,699 polygons (14,386 at M3, before the benches and this fix), and 0 of 3,000 sampled navmesh points lie inside geometry. The smoke and pedestrian tests check this now.
- **Give-way deadlock:** the first "junction clear" test counted cars waiting at the other stop lines, so two give-way lines waited for each other forever. Now only cars in the junction box, or arriving within 3 s, count.
- **Give-way livelock:** cars crept over the line and stopped again and again. Once the 1 s wait was done, the car sped up, its "waited" timer reset, and it was stopped again because its centre hadn't passed the stop node yet. A driver now remembers the line it was released at.
- **Traffic queued forever behind the parked sedans:** all three sedans from M3 are parked in the outer lane of a main road. Drivers now change lanes to pass them (GDD §6, "swerve or brake").
  - With very little room (one test case had 9 m), the swerve cut it fine, with 0.5 m between bodies.
  - Now the pull-out distance scales with the room available, and the driver tracks the path more tightly while passing, giving about 2.9 m beside the parked car.
- **A chatting pair stood on a bench:** `spawn_pair` offset the two people 0.6 m without checking the spots, and one landed inside the bench. Both spots must now be on the navmesh.
- **Knocked-down people ran into the car:** on getting up they ran from where the car had been, which was behind them, so they ran into it where it had stopped. They now run from where the car is.
- **Looks:**
  - A dark "collar shadow" box read as a black square on every chest; it's now a small skin-coloured neckline.
  - Sitting legs stuck straight out with the feet in the air. They now angle down to the ground, and the seat point moved forward so the thighs don't cut through the bench.
- **"ObjectDB instances leaked at exit":**
  - **Cause:** traffic engine sounds. `AudioManager.quit_game` stopped every sound, but during its 0.1 s wait running car engines started their sounds again.

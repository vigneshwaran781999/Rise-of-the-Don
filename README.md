# RISE OF THE DON

*THE CITY NEVER FORGIVES.*

An original 3D open-world action-adventure set in **Velanagar**, a fictional South Indian coastal city. Built with Godot 4 (GDScript only), with placeholder 3D art generated by Blender scripts.

**Status: Milestone 2 (first car).** Main menu → New Game drops you into a test city block where you can walk, run, sprint and jump with a third-person camera, then get into a parked sedan and drive it: chase and hood cameras, speedometer, horn, headlights and crash damage. See [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md) for the full design and milestone plan.

## Requirements

| Tool | Version | Needed for |
|---|---|---|
| Godot | 4.7.2 stable (standard or .NET build; the project uses no C#) | Opening and running the game |
| Blender | 4.0 or newer | Only to regenerate the 3D assets (the GLBs are already in the repo) |

## Open and run

1. Start the Godot editor and choose **Import**, then select this folder's `project.godot`.
2. Press **F5** (or the ▶ Play button). The game starts at the main menu.

From the command line (Git Bash), without opening the editor:

```bash
GODOT="/c/Users/ADMIN/Downloads/Godot_v4.7.2-stable_mono_win64/Godot_v4.7.2-stable_mono_win64/Godot_v4.7.2-stable_mono_win64.exe"
"$GODOT" --path .
```

The window opens at 1600×900; the game renders at a 1920×1080 base resolution and scales to the window.

## Controls

**On foot**

| Action | Keyboard / mouse | Gamepad |
|---|---|---|
| Move | W A S D | Left stick |
| Look | Mouse | Right stick |
| Walk (hold) | Ctrl | Tilt the left stick gently |
| Sprint (hold, uses stamina) | Shift | Left stick click |
| Jump | Space | A |
| Get in / out of a vehicle (within 3 m) | F | Y |

**Driving**

| Action | Keyboard / mouse | Gamepad |
|---|---|---|
| Accelerate | W or Up | RT |
| Brake; hold at a standstill to reverse | S or Down | LT |
| Steer | A / D or Left / Right | Left stick |
| Handbrake | Space | RB |
| Horn (hold) | H | Left stick click |
| Headlights on / off | L | D-pad up |
| Chase / hood camera | V | Back |
| Look around | Mouse | Right stick |
| Get out (brakes first if moving) | F | Y |

**General**

| Action | Keyboard / mouse | Gamepad |
|---|---|---|
| Pause menu | Esc | Start |
| FPS counter | F3 | — |
| Menus: move / select / back | Arrow keys / Enter / Esc | D-pad / A / B |

Also bound for a later milestone (does nothing yet): **E / X** interact.

If the mouse stops controlling the camera (for example after Alt+Tab), click in the game window.

The parked sedan is a few metres ahead of where you start, against the left kerb. If it ends up on its side or roof while you're in it, it rights itself after a couple of seconds. Crashes cost the car health (the CAR bar under the speedometer); below about a third it smokes, and at zero the engine dies until you start a new game.

## Settings

Main menu → Settings (or pause → Settings): master, music and effects volume, mouse sensitivity, invert look. Changes apply immediately and are saved to `%APPDATA%\Godot\app_userdata\Rise of the Don\settings.cfg` when you leave the screen.

## Project layout

```
scenes/      main/ (main menu, game), player/, vehicles/ (sedan), world/ (test block), ui/ (HUD, pause menu)
scripts/     player/, vehicles/, world/, ui/, systems/ (Settings and AudioManager autoloads, game session, camera hand-over)
resources/   tunables: characters/ (player movement and camera), vehicles/ (sedan handling, vehicle camera), world/ (lighting preset)
assets/      models/ (generated GLBs: road/, buildings/, props/, vehicles/, test/)
shaders/     menu background
tests/       smoke test, vehicle handling test, screenshot tool
tools/       blender/ (asset generators), godot/ (project setup script)
docs/        GAME_DESIGN.md
```

Tuning lives in resources, not code. Edit these in the Godot inspector:
- `resources/characters/player_tuning.tres`: speeds, jump, stamina, getting in and out of vehicles
- `resources/characters/player_camera.tres`: on-foot camera distance, sensitivity, smoothing
- `resources/vehicles/sedan_stats.tres`: the sedan's mass, engine, brakes, steering, suspension, tyre grip, gearbox sound, damage
- `resources/vehicles/vehicle_camera.tres`: chase distance, swing-back delay, speed field of view, hood view
- `resources/world/late_afternoon.tres`: sun, sky, fog

## Regenerating assets

All 3D models come from Python scripts in `tools/blender/`. To rebuild every model and re-import:

```bash
bash tools/blender/build_all.sh
```

Each generator can also be run alone and accepts asset names, e.g.
`"$BLENDER" --background --factory-startup --python tools/blender/buildings.py -- bld_shophouse_02`.
The scripts are deterministic: re-running produces identical files.

The input map, autoloads and audio buses are generated by `tools/godot/setup_project.gd`. Edit that script rather than the `[input]` section of `project.godot`, then run:

```bash
"$GODOT_CONSOLE" --headless --path . --script res://tools/godot/setup_project.gd
```

(`$GODOT_CONSOLE` is the `_console.exe` next to the editor executable.)

## Tests

```bash
# Headless smoke test: menu -> game -> movement, jump, kerbs, ramps, camera, HUD ->
# get in the sedan, drive, brake, reverse, steer, cameras, horn, lights, crash, get out -> pause -> menu
"$GODOT_CONSOLE" --headless --path . res://tests/smoke_test.tscn      # prints SMOKE TEST PASSED, exit code 0

# Vehicle handling test: prints a handling report (0-100, braking, turning, stability, damage...)
# --fixed-fps 60 runs the simulation as fast as the CPU allows (about 1.5 min without it)
"$GODOT_CONSOLE" --headless --path . --fixed-fps 60 res://tests/vehicle_test.tscn   # VEHICLE TEST PASSED

# Visual check: renders a scene in a window, saves a PNG and prints FPS / draw calls
"$GODOT_CONSOLE" --path . res://tests/screenshot.tscn -- --scene=res://scenes/main/game.tscn --out=C:/temp/shot.png
# ...or from the driver's seat after 2 s of throttle, with the hood camera:
"$GODOT_CONSOLE" --path . res://tests/screenshot.tscn -- --scene=res://scenes/main/game.tscn --out=C:/temp/drive.png --drive --throttle=120 --hood
```
